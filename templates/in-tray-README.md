# The in-tray

Drops waiting to be sorted: one page per message or thread, as `office
drop` captured it, instant and dumb. Nothing here is a job yet; jobs
are folders on the desk. What lives here, page by page:

- YYYY-MM-DD-slug.md, one drop each: the first line of the text as its
  heading, four field lines (dropped, project, via, status), and the
  text itself, verbatim, under `## Text`. The field lines are the office
  command's, never written by hand. Live: a sorted drop leaves the
  in-tray whole, its bytes as they are, into the folder it became, as
  drops/YYYY-MM-DD-slug.md.

Every session `office start` sends out while a drop here is unsorted
carries it: in the request for an office session, in the office's
context beside the request for a project session. A session that can
judge a drop sorts it in a `## Sort` section of its notes.md (doctrine
section 4). `office start --drop in-tray/PAGE` sends one drop straight
out as a project session, which sorts it first and does the work
second; `office start --sort` sends the drops nothing carried to a
session of their own. Nothing here is hung and nothing is filed.

When a session's Sort lands, office land files it on the drop's page as
a section at its end, the first line the office's and the rest the
session's, word for word, and sets the page's status to sorted (values
illustrative):

```
## Sort

- sorted: 2026-10-14, by 2026-10-14-alpha-login-error-001
- project: alpha
- folder: new
- goal: Fix the login page's error on narrow screens
- size: small
- tell: the sender, in reply: fixed in the next release
- facts: none

### Brief

<the subsection's Brief, verbatim>
```

A sorted page still here is a desk move: office moves (which office land
runs) mints the folder `new` asks for, or takes folder N, and moves the
page into it whole, with the Brief as the folder's brief.md.
